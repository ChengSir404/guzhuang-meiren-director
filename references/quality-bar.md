# 提示词质量诊断与成品标杆

当用户说“差点意思、再丰富、没有气韵、不够惊艳、脸不清楚、像影楼、像参数表、人物太僵、背景太假”或提供旧提示词要求改进时读取。先在心中诊断，按任务范围交付替换段落或完整成品；只有用户要求分析时才解释诊断过程。

先按 [control-workflow.md](control-workflow.md) 判断失败修复模式。若用户提供生成结果，先查看整幅画面的构图、动作和主次，再查看脸部区域的五官、光线、皮肤和遮挡；不能只读原提示词猜问题。

## 单变量原则

每轮只选一个最上游主变量，或一组不可拆开的强耦合变量。比如“脸太小”在允许改构图时先调整景别和人物占比；只有仍存在具体问题时才继续调整背景或对焦；但不能顺手更换脸型、发髻、裙色、动作和庭院。其余用户已满意的内容必须写入保持项。

## 症状与窄范围修复

| 症状 | 常见原因 | 优先修复 |
|---|---|---|
| 漂亮但空 | 没有当下事件和情绪潜台词 | 增加刚刚发生/即将发生的一拍，让眼神与动作透露未说出口的情绪 |
| 像服装商品页 | 名词多，人物与衣服没有因果 | 只留一个主轮廓、一个工艺焦点；写衣料如何受光、受风、受动作 |
| 像影楼写真 | 正面站姿、对称布景、装饰平均用力 | 改成决定性瞬间、非中心构图、前景遮挡和有方向的留白 |
| 人物僵硬 | 双手无任务，重心与视线不明确 | 写清双手、重心、视线对象与下一拍动作 |
| 背景像贴纸 | 只罗列亭台、花瓣、烟雾 | 增加季节/时辰/天气证据，以及风、水、光或尘土对人物的反馈 |
| 有“电影感”但画面平 | 没有真实光源、景深和色彩控制 | 指定主光、环境补光、前中后景遮挡、焦点和三色关系 |
| 每个人长得一样 | 只写完美五官、白皙皮肤、杏眼红唇 | 改用 3–4 个身份相关辨识点与一个极轻微不对称/生活痕迹 |
| 美女不够惊艳 | 真实性有了，但脸部对比、色彩焦点、眼神事件和构图权重不足 | 选择一种美貌方向，拉近景别，用眉眼主对比、一个色彩记忆点和有对象的瞬时眼神建立第一眼冲击 |
| 脸不清楚或五官发糊 | 人脸在画面中过小、9:16 同时塞入高髻全身长裙和大庭院、极浅景深、动态模糊、遮挡、逆光或背景信息过载 | 在 9:16 中改为腰上至大腿中部中近景，提高人物与脸部占比；近正面、双眼同焦、面部独立补光，运动模糊只落在衣摆或背景，删除遮脸元素 |
| 动作故事前后矛盾 | 没有先定位事件来源，导致声音、视线、头部、身体和留白各指不同方向 | 先标出来源方位，再按眼神→头部→肩线→重心→构图留白的顺序统一响应；若人物故意不回头，应明确余光或克制停顿 |
| 华丽但廉价 | 金银珠玉和纹样同时堆满 | 限制主发饰、面料、工艺、金属和点睛色数量，拉开哑光与亮面层次 |
| 身材像塑料模型 | 体型参数脱离服装结构、姿态与重力 | 先恢复叠穿、腰线、袖裙结构，再让衣褶随坐、走、骑、转身变化 |
| 信息很多但模型抓不住重点 | 所有细节权重相同，正负词重复 | 重排为三级视觉锚点，只保留 5–8 个会改变画面的关键细节 |
| 提示词很长但结果仍漂移 | 同一要求跨章节重复，颜色、服装、发饰、动作和背景仍保留多个“或/可加入”选项 | 先替用户选定唯一方案，再把重复内容合并到对应层；删除独立“细节强化”复读段，结尾只留一次关键约束 |

## 修订顺序

1. 保留用户不能改变的主体、时代、动作、配色或参考图身份。
2. 用一句画面核补足事件与潜台词；不要先添加更多饰品。
3. 选定第一视觉锚点，并删除争抢焦点的元素。
4. 若人物以美貌为主体，先确认景别足以看清双眼、鼻唇和神态；不够则拉近构图，再继续补妆造。
5. 标出事件或声音来源，统一眼神、头肩、重心、手部任务与留白方向。
6. 让人物身份决定脸、衣、道具；让动作决定重心、衣褶、发饰和环境反馈。
7. 用镜头、光源、色彩和材质统一画面。
8. 最后压缩同义词和通用负面词，避免修订后比原稿更臃肿。
9. 检查未决的设计分支并选择一个方案；保留“不裸露或透视”等正常语法，不机械删除所有“或”。
10. 记录本轮唯一修复变量；若重写后的变化超过这一范围，回退多余改动。

## 标杆与验证

需要完整导演版范例时按需读 [成品示例](../examples/director-prompts.md)；回归请求与验收条件见 [行为用例](../examples/behavioral-cases.md)。不必为一次局部修复加载全部标杆。

症状表中的修复办法只在用户允许的范围内选用；锁定全身、侧脸、静态姿态或构图时保留这些要求。脸部清晰度修复不得自动改变人物签名；没有出图时只提出原因假设。输出格式以 [提示词架构](prompt-architecture.md) 为准。
